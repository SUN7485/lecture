# KNOWN ISSUES — every known-unfixed bug, with its trigger
<!-- If it bit us once and isn't fixed, it lives here until it is. -->

- **Gemini image model quota** (Electron Studio image lab): image generation fails on quota. Trigger: any image-lab generate in `src/studio/`. Needs quota fix / key upgrade. Parked since web pivot.
- **Slide split leaves authored footer numbers stale** (v5 text-overload fix, 2026-07-17): decks that hardcode «شريحة N من M» in their footer keep the old numbers after a split (footer is authored content; the app only renumbers `data-ve-figure` figures). Trigger: fix-all on an overloaded slide in a deck with numbered footers, e.g. `2.html`. Candidate fix: detect the exact «شريحة N من M» pattern inside `.footer*` elements and renumber on commit — decide deliberately, it edits authored text.
- **Preset faces dedupe to one subset per weight** (accepted, parity with web since 017): `fetchGoogleFontFaces` keeps arabic+latin subset faces but `dedupeFonts` keys on family|weight|style, so one subset's woff2 serves all codepoints (kit `_fontFace` emits no `unicode-range`). Latin digits render from the arabic-subset file — fine for Google's Arabic families (they include basic Latin), would clip for families whose subsets don't overlap. Trigger: only if a future preset uses such a family.
- **~~Electron doctor dock on old row UI~~ → RESOLVED 2026-07-16**: `src/renderer.js` + `src/styles.css` now render the v4 root-cause cards (aggregate → `doctorCard()`, count pill, clickable chips, fix-all-in-one-undo, score counts cards, «العرض كله» deck chip, Rule 19b `fonts-external`). Kept Electron's **light** dock theme rather than porting the web's dark redesign (a dark panel on the light app chrome would look broken; parity was functional, not cosmetic). Verified live via playwright-core + `LVE_OPEN` on `Chp1-Lec1-2.html`: 3 cards, score 80, screenshot confirms. Note: Electron opens from the real file dir so `broken-image` doesn't fire (image resolves) — 3 cards vs web's 4, both correct.
- **Doctor chip focus-scroll needs real Chrome** (not a bug): `focusIssue()` uses `scrollTo({behavior:'smooth'})`, which the in-app preview browser doesn't animate (flash-outline still fires, proving the wiring). Renders/scrolls normally in a real browser. Trigger: verifying chip-click scrolling via the preview pane — check the flash, not the scrollTop.
- **Deck-CSS specificity beats kit fonts** (accepted limit, by design): decks whose own CSS targets titles with higher specificity than `.slide h1` keep their font when a kit/typography is applied. Trigger: imported decks with aggressive stylesheets. Popover live sample makes it visible; no fix planned.
- **~~Doctor silent on external `@import`~~ → RESOLVED 2026-07-16 by Rule 19b** (`fonts-external`, commit `c698efa`): the doctor now emits a deck-level warn when the deck loads fonts from a web-font host (`@import`/`<link>` to fonts.googleapis.com, typekit, bunny, …), routing the user to 🔤 embed. Verified firing on `Chp1-Lec1-2.html` (Cairo, score 72→68), silent on clean templates. **Deliberate boundary (not a bug):** a distinctive *local-install* font that HAS a generic fallback (e.g. templates' `'Diodrum Arabic', 'Cairo', sans-serif`) is still NOT flagged — it degrades to the fallback rather than tofu, and flagging every such stack would nag the responsible offline-stack design v4 exists to respect. Only the network-dependency case (a fact, zero false positives) is surfaced.
